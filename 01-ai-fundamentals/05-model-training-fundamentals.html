Model Training Fundamentals

Understand parameters, weights, bias, loss, gradient descent, learning rate, batches and epochs.

1. Parameters: weights and bias

Parameters are internal values learned during training. Weights control the influence of inputs; bias shifts the weighted sum independently of input values.

Example weights such as 0.4, 0.5 and 0.1 are illustrative, not causal explanations or a real trained model.

Terminology: learned bias parameter is not the same as high bias in bias–variance.

2. Parameters vs hyperparameters

Parameters (learned)Hyperparameters (configured / tuned)
Weights and biasesLearning rate, batch size, epochs

3. Loss and optimization

Loss measures prediction error under a chosen objective. An optimizer uses gradient information to update parameters in an attempt to reduce loss.

Simplified gradient descent update:

w_new = w_old − η × (∂L / ∂w)

η is the learning rate. Too high: updates may overshoot or become unstable. Too low: training can be very slow.

4. Batch, step and epoch

Batch

A group of examples processed together.

Step

Typically one optimizer update.

Epoch

One complete pass through the training dataset.

Example: 10,000 records ÷ batch size 100 = 100 batches/steps per epoch. Over 20 epochs, approximately 2,000 optimizer steps (assuming one update per batch).

5. Infrastructure implications

  • CPU/GPU executes data and model computations.
  • RAM/VRAM holds batches, parameters, activations and optimizer state.
  • Storage holds datasets, checkpoints and artifacts.
  • Networking moves data between workers and storage.

Training is often run as a repeatable Kubernetes Job with resource requests, data access, logs, retries and checkpoint persistence.

Practical exercise

Initial weights: CPU 0.2, memory 0.3, restarts 0.1. Learning rate 0.01, batch size 100, 10,000 records, 20 epochs. Identify parameters and hyperparameters, calculate steps, and explain loss and the effect of a high learning rate.
